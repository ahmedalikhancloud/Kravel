First time here? A 60-second guide to reading a trace
  1. Open this question’s trace. Select kravel.debugger → Inputs / Outputs for the recorded question and answer.
  2. Follow the checks. Select guardrail.input or guardrail.input.semantic. Expand its classifier to inspect the decision and latency. A blocked request may stop before Qwen or any cluster reads.
  3. Follow the investigation flow. In MLflow enable Show execution timeline for span timings. Inspect evidence.*, tool.*, graph.route, qwen.inference, then guardrail.output. Only steps that actually ran are recorded.
  4. Check the second opinion. Open evaluations below the answer; select a saved job or start Quick. Expand a scorer → Inspect judge request & result → judge.local_inference for the actual model exchange. Deterministic checks have no model call.
  5. Read outcomes, not just checkmarks. A finished scorer can still say “no.” Skips and errors are not passing scores. Saved reports include reference facts and full job results; same-model judging can be biased.

Returned rationales are not hidden chain-of-thought. Traces are bounded and redacted on a best-effort basis: use non-sensitive demo data and review before sharing.
